# 🔓 1. Hashcat

> [!info] 🧠 What Is Hashcat?  
> **Hashcat** is a widely used password-cracking tool for **Linux, Windows, and macOS**. It supports a large variety of hash types and has strong **GPU support**, making it particularly effective for high-speed password cracking.
> 
> Hashcat was proprietary from **2009–2015** and has since been released as **open-source**.

### 🧠 Hashcat vs John the Ripper

|Feature|🧔 John the Ripper|⚡ Hashcat|
|---|---|---|
|Platforms|Linux/Unix-focused origins|Linux, Windows, macOS|
|GPU support|✅|⭐ Excellent|
|Hash types|Hundreds|Hundreds|
|Attack modes|Single, Wordlist, Incremental, etc.|Dictionary, Mask, Combinator, Association, etc.|
|Main strength|Flexible cracking framework|🚀 High-performance GPU cracking|

> [!important] 🎯 Mental Model  
> **Hashcat = hash type + attack mode + attack data**
> 
> Before running Hashcat, determine:
> 
> ```text
> What hash is this?
>        ↓
> What is its Hashcat mode ID?
>        ↓
> What attack mode fits the situation?
>        ↓
> What wordlist / rules / mask should I use?
> ```

# ⚙️ 2. Hashcat Basic Syntax

The general syntax is:

```bash
hashcat -a 0 -m 0 <hashes> [wordlist, rule, mask, ...]
```

### 🔍 Arguments

|Argument|Purpose|
|---|---|
|`-a`|Specifies the **attack mode**|
|`-m`|Specifies the **hash type / mode ID**|
|`<hashes>`|Hash string or file containing hashes|
|`[wordlist, rule, mask, ...]`|Additional arguments required by the selected attack|

Example:

```bash
hashcat -a 0 -m 0 hashes.txt /usr/share/wordlists/rockyou.txt
```

Breakdown:

```text
-a 0
 │
 └── Dictionary attack

-m 0
 │
 └── MD5

hashes.txt
 │
 └── Target hashes

rockyou.txt
 │
 └── Candidate passwords
```

# 🔢 3. Hashcat Hash Types

Hashcat assigns each supported hash type a numerical **Hashcat mode ID**.

To view the supported hash modes:

```bash
hashcat --help
```

Example:

|Hashcat ID|Hash Type|
|--:|---|
|`0`|MD5|
|`100`|SHA1|
|`900`|MD4|
|`1300`|SHA2-224|
|`1400`|SHA2-256|
|`10800`|SHA2-384|
|`1700`|SHA2-512|
|`17300`|SHA3-224|
|`17400`|SHA3-256|
|`17500`|SHA3-384|
|`17600`|SHA3-512|
|`6000`|RIPEMD-160|
|`600`|BLAKE2b-512|
|`6100`|Whirlpool|
|`10100`|SipHash|

There are many additional formats.

> [!important] 🧠 Remember  
> **JtR and Hashcat use different identifiers for hash types.**
> 
> For example:
> 
> ```text
> MD5
> ├── JtR → raw-md5
> └── Hashcat → 0
> ```

# 🔎 4. Identifying Hashcat Modes with hashID

When you encounter an unknown hash, `hashID` can provide possible hash types.

For Hashcat mode IDs, use:

```bash
hashid -m '<hash>'
```

Example:

```bash
hashid -m '$1$FNr44XZC$wQxY6HHLrgrGX0e1195k.1'
```

Example result:

```text
[+] MD5 Crypt [Hashcat Mode: 500]
[+] Cisco-IOS(MD5) [Hashcat Mode: 500]
[+] FreeBSD MD5 [Hashcat Mode: 500]
```

Therefore:

```text
Hash
 │
 ▼
hashid -m
 │
 ▼
Possible Hash Types
 │
 ▼
Hashcat Mode ID
 │
 ▼
-m <ID>
```

> [!warning] ⚠️ Hash Identification Is Not Always Certain  
> `hashID` can produce **multiple possible formats** for an ambiguous hash.
> 
> Always consider the **context in which the hash was obtained** before selecting the final Hashcat mode.

# 📖 5. Dictionary Attack — `-a 0`

Hashcat's **dictionary attack** uses a wordlist and tests each entry as a potential password.

The attack mode is:

```text
-a 0
```

### General Syntax

```bash
hashcat -a 0 -m <hash_mode> <hash> <wordlist>
```

Example:

```bash
hashcat -a 0 -m 0 e3e3ec5831ad5e7288241960e5d4fdb8 /usr/share/wordlists/rockyou.txt
```

Here:

```text
-a 0
 │
 └── Dictionary attack

-m 0
 │
 └── MD5

e3e3ec...
 │
 └── Target hash

rockyou.txt
 │
 └── Candidate passwords
```

Hashcat tests:

```text
rockyou.txt
     │
     ├── password  → MD5 → compare
     ├── 123456    → MD5 → compare
     ├── qwerty    → MD5 → compare
     ├── ...
     └── candidate → MD5 → 🎯
```

# 📊 6. Understanding Hashcat Output

A successful cracking session contains useful information.

For example:

```text
Session..........: hashcat
Status...........: Cracked
Hash.Mode........: 0 (MD5)
Hash.Target......: e3e3ec5831ad5e7288241960e5d4fdb8
Guess.Base.......: File (/usr/share/wordlists/rockyou.txt)
Recovered........: 1/1 (100.00%) Digests
Progress.........: 28672/14344385 (0.20%)
```

### 🔍 Important Fields

|Field|Meaning|
|---|---|
|`Status`|Current state, e.g. `Cracked`|
|`Hash.Mode`|Hashcat mode being used|
|`Hash.Target`|Target hash|
|`Guess.Base`|Main candidate source|
|`Guess.Mod`|Additional modifier such as rules|
|`Recovered`|Number of hashes successfully cracked|
|`Progress`|Number of candidates processed|
|`Speed`|Current cracking speed|
|`Guess.Mask`|Mask used during mask attacks|
|`Candidates`|Candidate passwords currently being tested|
|`Hardware.Mon`|Hardware utilization information|

> [!success] 🎯 Exam Recognition  
> If you see:
> 
> ```text
> Status...........: Cracked
> Recovered........: 1/1
> ```
> 
> the target hash has successfully been cracked.

# 🛠️ 7. Wordlists + Rules

A wordlist alone may not be sufficient.

For example, the wordlist might contain:

```text
password
```

But the actual password might be:

```text
Password1!
P@ssword
password123
```

Hashcat can apply **rules** to wordlist entries to generate additional candidates.

### Rule Syntax

```bash
hashcat -a 0 -m <hash_mode> <hash> <wordlist> -r <ruleset>
```

Example:

```bash
hashcat -a 0 -m 0 1b0556a75770563578569ae21392630c \
/usr/share/wordlists/rockyou.txt \
-r /usr/share/hashcat/rules/best64.rule
```

### 🧠 Attack Structure

```text
              Wordlist
                 │
                 ▼
          "password"
                 │
                 ▼
        ┌─────────────────┐
        │   Rule Engine   │
        └────────┬────────┘
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
  Password1   p@ssword   Password!
       │         │         │
       └─────────┼─────────┘
                 ▼
           Hash candidates
                 │
                 ▼
             Compare
```

# 🎭 9. Mask Attack — `-a 3`

A **mask attack** is a controlled brute-force attack where the attacker explicitly defines the password's structure.

The attack mode is:

```text
-a 3
```

Instead of testing every possible password, you define the expected character pattern.

### Example

Suppose you know the password is:

```text
6 letters + 2 numbers
```

Rather than testing every possible password, the mask restricts the search space to that structure.

This is the fundamental idea:

```text
❌ Unrestricted brute force

Everything
   │
   └── Huge search space


✅ Mask attack

Known structure
      │
      ├── Character 1
      ├── Character 2
      ├── ...
      ├── Character 7
      └── Character 8
             │
             ▼
       Much smaller search
```

# 🔤 10. Built-in Hashcat Character Sets

Hashcat provides predefined character-set symbols.

|Symbol|Character Set|
|---|---|
|`?l`|Lowercase: `abcdefghijklmnopqrstuvwxyz`|
|`?u`|Uppercase: `ABCDEFGHIJKLMNOPQRSTUVWXYZ`|
|`?d`|Digits: `0123456789`|
|`?h`|Hex lowercase: `0123456789abcdef`|
|`?H`|Hex uppercase: `0123456789ABCDEF`|
|`?s`|Special characters / symbols|
|`?a`|Lowercase + uppercase + digits + special characters|
|`?b`|All bytes: `0x00`–`0xff`|

### 🧠 Easy Memory Trick

```text
?l → lower
?u → upper
?d → digit
?s → symbol
?a → all printable character classes
```

# 🧩 11. Custom Character Sets

Hashcat allows custom character sets using:

```text
-1
-2
-3
-4
```

These are then referenced inside a mask as:

```text
?1
?2
?3
?4
```

Conceptually:

```text
-1 <custom charset>
      │
      ▼
    ?1 in mask
```

This allows you to build masks specifically around the password characteristics you expect.

# 🎯 12. Building a Mask

Suppose you know the password follows this structure:

```text
Uppercase
+
4 lowercase letters
+
1 digit
+
1 symbol
```

The mask becomes:

```text
?u?l?l?l?l?d?s
```

Breakdown:

```text
?u → Uppercase
?l → Lowercase
?l → Lowercase
?l → Lowercase
?l → Lowercase
?d → Digit
?s → Symbol
```

Visualized:

```text
┌───┬───┬───┬───┬───┬───┬───┐
│ U │ l │ l │ l │ l │ d │ s │
└───┴───┴───┴───┴───┴───┴───┘
 1   2   3   4   5   6   7
```

# 📐 14. Mask Attacks Reduce the Keyspace

This is one of the most important concepts in password cracking.

Suppose the attacker knows:

```text
7 characters
Uppercase + lowercase + digit + symbol pattern
```

They don't need to test passwords outside that structure.

### 🧠 Mental Model

```text
                    All Possible Passwords
                            │
                            ▼
                  ┌─────────────────────┐
                  │ Known Information   │
                  │                     │
                  │ Length = 7          │
                  │ Position 1 = Upper  │
                  │ Positions 2-5 = Low │
                  │ Position 6 = Digit  │
                  │ Position 7 = Symbol │
                  └──────────┬──────────┘
                             │
                             ▼
                      Reduced Keyspace
                             │
                             ▼
                       Faster Cracking
```

> [!important] 🎯 CPTS Principle  
> **Every piece of information about the password can reduce the cracking keyspace.**
> 
> Usernames, password length, known prefixes/suffixes, character classes, leaked passwords, organizational conventions, and other clues can all help construct a more efficient attack.

# ⚔️ 15. Dictionary vs Mask Attacks

|Feature|📖 Dictionary `-a 0`|🎭 Mask `-a 3`|
|---|---|---|
|Candidate source|Wordlist|Generated dynamically|
|Requires wordlist|✅|❌|
|Uses known password structure|Limited|⭐ Excellent|
|Good for common passwords|⭐⭐⭐|⭐⭐|
|Good for structured passwords|⭐⭐|⭐⭐⭐|
|Search space|Wordlist-dependent|Mask-dependent|
|Example|`rockyou.txt`|`?u?l?l?l?d?s`|

### 🧠 When to Use Which?

```text
Do I have a good password wordlist?
          │
         Yes
          ▼
     📖 Dictionary
          │
          ▼
      Failed?
          │
          ▼
   Add password rules
          │
          ▼
      Still failed?
          │
          ▼
Do I know the password structure?
          │
         Yes
          ▼
      🎭 Mask attack
```

# 🔥 16. JtR vs Hashcat — Attack Concepts

The two tools overlap heavily.

|Concept|JtR|Hashcat|
|---|---|---|
|Dictionary|`--wordlist=`|`-a 0`|
|Rules|`--rules`|`-r <ruleset>`|
|Brute-force-style|`--incremental`|`-a 3` mask|
|Hash format|`--format=`|`-m <ID>`|
|File conversion|`*2john`|Often uses Hashcat-compatible extraction/conversion|
|GPU focus|Available|⭐ Major strength|

> [!important] 🧠 Don't Mix the Syntax
> 
> **JtR:**
> 
> ```bash
> john --wordlist=rockyou.txt hashes.txt
> ```
> 
> **Hashcat:**
> 
> ```bash
> hashcat -a 0 -m 0 hashes.txt rockyou.txt
> ```
> 
> They perform similar tasks but use **different command syntax and hash identifiers**.
