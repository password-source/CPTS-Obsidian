# 🗄️ 1. Cracking Protected Archives

> [!info] 🎯 Objective  
> Password-protected archives are common during penetration tests and post-exploitation. They may contain multiple files such as documents, credentials, backups, configuration files, or other sensitive information.
> 
> **General methodology:**
> 
> ```text
> 🔎 Find Archive
>      ↓
> 🧬 Identify Format
>      ↓
> 🔑 Extract Crackable Hash / Representation
>      ↓
> 💥 Crack Password Offline
>      ↓
> 🔓 Decrypt / Extract Archive
>      ↓
> 📂 Analyze Contents
> ```
> 
> **Mental Model:** An archive is a **container**. Cracking its password may provide access to everything stored inside it.

## 📦 2. Why Organizations Use Archives

Instead of transferring multiple files individually:

```text
Excel.xlsx
Report.pdf
Analysis.docx
Presentation.pptx
```

employees can organize them into folders and compress everything into one archive:

```text
📁 Project/
├── 📄 Analysis.docx
├── 📊 Report.xlsx
├── 📕 Summary.pdf
└── 📽️ Presentation.pptx
        ↓
    🔐 Project.zip
```

> [!important] 🧠 Security Perspective  
> A single protected archive may contain **many valuable files**. Obtaining the archive password can therefore expose considerably more information than compromising one standalone document.

## 🗂️ 3. Common Archive / Compressed Formats

|Extension / Format|Description|
|---|---|
|`.tar`|TAR archive|
|`.gz` / `.gzip`|GZIP compression|
|`.rar`|RAR archive|

> [!tip] 🔎 Don't Memorize Every Extension  
> There are hundreds of archive formats. When encountering an unfamiliar extension:
> 
> 1. Identify the format.
>     
> 2. Determine whether it supports encryption.
>     
> 3. Identify the tool required to extract or crack it.
>     

## 🔎 4. Enumerating Archive Extensions

Instead of manually maintaining a list of archive extensions, we can retrieve them automatically from a reference website:

```bash
curl -s https://fileinfo.com/filetypes/compressed | html2text | awk '{print tolower($1)}' | grep "\." | tee -a compressed_ext.txt
```

Example output:

```text
.mint
.zhelp
.b6z
.fzpz
.zst
.apz
.ufs.uzip
.vrpackage
.sfg
.gzip
.xapk
.rar
.pkg.tar.xz
```

### 🧠 Command Breakdown

```text
curl
 │
 └── Download webpage
        ↓
html2text
 │
 └── Convert HTML → text
        ↓
awk '{print tolower($1)}'
 │
 └── Extract first field + convert to lowercase
        ↓
grep "\."
 │
 └── Keep entries containing "."
        ↓
tee -a compressed_ext.txt
 │
 ├── Display results
 └── Append results to compressed_ext.txt
```

> [!info] 📌 Module Context  
> At the time the material was written, the referenced website listed **365 archive file types**, demonstrating why memorizing every format is impractical.

## 🔐 5. Compression ≠ Encryption

Not every archive format supports native password protection.

For example, TAR is primarily an **archive format**, and encryption may instead be applied using another tool:

```text
📦 TAR Archive
     │
     ├── OpenSSL
     │
     └── GPG
          ↓
     🔐 Encrypted Data
```

Therefore:

```text
.tar
  ≠
"the TAR format itself is encrypted"
```

> [!warning] ⚠️ Important  
> The file extension alone does **not necessarily reveal the encryption mechanism**.
> 
> A file may have an extension associated with compression while encryption was applied separately.

## 🧬 6. Identify the Actual File Type

When the extension is misleading or unfamiliar, use:

```bash
file <filename>
```

Example:

```bash
file GZIP.gzip
```

Output:

```text
GZIP.gzip: openssl enc'd data with salted password
```

This tells us that despite the `.gzip` filename, the actual contents are **OpenSSL-encrypted data using a salted password**.

> [!important] 🧠 Mental Model  
> **Filename extension = hint**
> 
> **`file` = evidence**
> 
> ```text
> GZIP.gzip
>     ↓
> file GZIP.gzip
>     ↓
> OpenSSL encrypted data
>     ↓
> Choose the appropriate attack method
> ```

## 🗜️ 7. Cracking ZIP Files

ZIP is one of the most commonly encountered archive formats, particularly in Windows environments.

The workflow is similar to cracking protected documents:

```text
🔐 ZIP.zip
    ↓
zip2john
    ↓
zip.hash
    ↓
John the Ripper
    ↓
🔑 Password
    ↓
📂 Extract Contents
```

### 🔑 Step 1 — Extract the ZIP Hash

```bash
zip2john ZIP.zip > zip.hash
```

Inspect the generated hash:

```bash
cat zip.hash
```

Example:

```text
ZIP.zip/customers.csv:$pkzip2$1*2*2*0*2a*1e*490e7510*0*42*0*2a*490e*409b*ef1e7feb7c1cf701a6ada7132e6a5c6c84c032401536faf7493df0294b0d5afc3464f14ec081cc0e18cb*$/pkzip2$:customers.csv:ZIP.zip::ZIP.zip
```

The important concept is that `zip2john` converts the protected ZIP into a **JtR-compatible hash representation**.

### 💥 Step 2 — Crack the Hash

```bash
john --wordlist=rockyou.txt zip.hash
```

Example:

```text
Using default input encoding: UTF-8
Loaded 1 password hash (PKZIP [32/64])
Will run 2 OpenMP threads
Press 'q' or Ctrl-C to abort, almost any other key for status
1234             (ZIP.zip/customers.csv)
1g 0:00:00:00 DONE
```

The recovered password is:

```text
1234
```

### 🔍 Step 3 — Display the Cracked Password

```bash
john zip.hash --show
```

Output:

```text
ZIP.zip/customers.csv:1234:customers.csv:ZIP.zip::ZIP.zip

1 password hash cracked, 0 left
```

> [!success] 🎯 ZIP Workflow
> 
> ```text
> ZIP.zip
>    ↓
> zip2john ZIP.zip > zip.hash
>    ↓
> john --wordlist=rockyou.txt zip.hash
>    ↓
> john zip.hash --show
>    ↓
> Password recovered
> ```

## 🔒 8. Cracking OpenSSL-Encrypted GZIP Files

Some file types do not natively support password protection, so encryption may have been applied externally.

For example:

```text
GZIP data
   +
OpenSSL encryption
   ↓
Password-protected file
```

First determine what the file actually contains:

```bash
file GZIP.gzip
```

Example:

```text
GZIP.gzip: openssl enc'd data with salted password
```

### 🧠 Why This Matters

If we incorrectly assume:

```text
GZIP.gzip → normal GZIP archive
```

we may use the wrong tool.

Instead:

```text
file
 ↓
OpenSSL encrypted data
 ↓
Use OpenSSL to test passwords
```

## 💥 9. Brute-Forcing an OpenSSL-Encrypted GZIP

OpenSSL-encrypted files can present a challenge because password attempts may produce **false positives**.

A more reliable method is to attempt to decrypt the file and immediately pipe the result into the expected extraction process.

```bash
for i in $(cat rockyou.txt);do openssl enc -aes-256-cbc -d -in GZIP.gzip -k $i 2>/dev/null| tar xz;done
```

### 🧠 How the One-Liner Works

```text
rockyou.txt
     │
     ▼
for i in $(cat rockyou.txt)
     │
     │  Try each
```
